# Ad Studio Light

**Meta広告（Facebook / Instagram）の「成果分析 → 勝ちパターン抽出 → 新バナー生成」を、自分のPC1台で完結できるツールです。**

📖 **使い方マニュアル: https://design-ad-studio-manual.vercel.app/** — 各画面でできることをスクリーンショット付きで解説しています

サーバー構築・デプロイは不要。ダウンロードして起動すれば、ブラウザからすぐ使えます。広告データやAPIキーが外部のサーバーに送られることはありません（保存先はすべて自分のPCの中です）。

## できること

```
📊 分析        Meta広告の実績を自動取得し、CPAランク・★評価で「勝ち広告」を特定
    ↓
🎨 生成        勝ち広告を起点に、AIで新しいバナー案を量産（コピー差替・テーマ替え）
    ↓
📚 学習        生成→入稿したバナーの勝敗を自動追跡し、次の生成に実績を反映
```

### 画面の機能一覧

| タブ | できること |
|------|-----------|
| 広告レポート | クリエイティブ別の成果分析。期間・媒体・配置・性別・年齢での深掘り、AI改善案、キャンペーン/広告セット絞り込み、異常検知アラート（消化急増・配信停止疑い・CPA急騰など） |
| 優先順位 | 広告名の名寄せ集計 → CPAランクA〜E・消化ランク・総合評価（★★★優秀〜損切り）で「伸ばす広告・止める広告」を一覧化 |
| 勝ちセグメント | 性年齢・配置別に勝ちパターンを抽出（要PostgreSQL・後述） |
| 勝ち分析再現 | 勝ち広告の「なぜ効いているか」をAIが分析し、その構造を引き継いだ新案を生成。別ブランドへの流用も可能 |
| バナー作成 / 素材から生成 / バリエーション作成 | キャッチコピーや手持ち素材からのAIバナー生成。商品画像・書籍などを「変更禁止素材」として渡し、描き替えずに配置させることも可能 |
| 生成履歴 | 生成した全バナーの履歴。採用すると入稿名（`YYYYMMDD_素材名`）が発行され、その名前で入稿するだけで勝敗が自動で紐づく |
| アカウント管理 | 分析対象の広告アカウント登録・同期・評価基準（報酬単価・ROAS基準）の設定 |

各画面のスクリーンショット付きの説明は **[使い方マニュアル](https://design-ad-studio-manual.vercel.app/)** を参照してください（同内容のMarkdown版: [docs/MANUAL.md](./docs/MANUAL.md)）。

## 必要なもの

| もの | 必須？ | 用途 |
|------|-------|------|
| **Node.js 20.9 以上** | ✅ 必須 | アプリの実行（[nodejs.org](https://nodejs.org/) からLTS版をインストール） |
| **Metaアクセストークン** | 分析に必須 | 自分の広告アカウントの実績取得（取り方は後述） |
| **OpenAI か Gemini のAPIキー** | 生成に必須 | AIバナー生成・AI分析（どちらか片方でOK） |
| PostgreSQL | 任意 | 一部の機能で使用（無くてもほぼ全機能が動きます・後述） |

APIキーが1つも無くても起動と画面確認はできます。まず起動してみて、使いたい機能に応じてキーを足していく形でOKです。

## セットアップ（5分）

```bash
git clone https://github.com/ReplusAsiaOrg/design-ad-studio-light-oss.git
cd design-ad-studio-light-oss
npm install
cp .env.example .env.local    # ← APIキーを記入（後からでもOK）
npm run dev
```

ブラウザで **http://127.0.0.1:3000** を開けば起動完了です。

> **Node.jsのバージョン確認**: `node -v` が `v20.9` 未満の場合は起動に失敗します。先に Node.js を更新してください（つまずきポイントNo.1です）。

### まず触ってみたい人へ：デモモード（APIキー・トークン不要）

```bash
npm run demo
```

Meta のトークンや PostgreSQL が無くても、**架空の化粧品ブランド「LUMINA（サンプル）」の広告実績**（22広告・約4ヶ月分・年齢×性別・配置内訳つき）で、広告レポート／優先順位／勝ちセグメント／勝ち分析再現など全タブを触れます。

- 実在のクライアント・アカウントのデータは一切含みません（数字はシード固定の乱数で毎回同じ）
- 画面右上に **DEMO** バッジが出ます。Meta API には接続しません（アカウント管理の「同期」もサンプルデータを取り直すだけ）
- DB は組み込みPostgres（PGlite）を `data/demo-db/` に自動作成します（初回起動時に10〜20秒かかります。削除すれば作り直されます）。`.env.local` に `DATABASE_URL` があっても**デモでは使いません**（実運用DBに架空データが混ざらない）
- `.env.local` に `OPENAI_API_KEY` / `GEMINI_API_KEY` を入れておけば AI分析・バナー生成も実際に動きます
- セミナー・社内説明・スクリーンショット素材にはこのモードを使ってください

### Metaアクセストークンの取り方

1. [Meta Business Suite](https://business.facebook.com/) → ビジネス設定 → 「システムユーザー」を作成（既にあればそれでOK）
2. システムユーザーに、分析したい広告アカウントを「閲覧」権限で割り当て
3. 「トークンを生成」で **`ads_read`** 権限を付けてトークンを発行
4. 発行されたトークンを `.env.local` の `META_ACCESS_TOKEN=` に貼り付け

このツールは読み取り（ads_read）しか使いません。広告の作成・変更・配信操作は一切行わないので、`ads_management` 権限は不要です。

## 最初の10分の使い方

1. **アカウント登録**: 右上「アカウント管理」→「広告アカウントを追加」→ 一覧から選んで登録
2. **同期**: 登録したアカウントの「同期」を押す → Metaから実績が取り込まれる
3. **分析を見る**: ホームでアカウントを選ぶと広告レポートが開く。「優先順位」タブで★評価を確認
4. **生成する**: 「勝ち分析再現」で勝ち広告を選ぶ → AIが分析 → 新案を生成 → ダウンロード
5. **学習ループを回す**（おすすめ）: 生成したバナーを入稿すると決めたら「生成履歴」タブで「採用」→ 発行された入稿名（例 `20260809_夏の限定訴求A`）を**そのままMetaの広告名にして入稿** → 後日「成果を更新」を押すと勝敗が自動で紐づき、以降の生成AIが「勝った切り口・負けた切り口」を踏まえるようになります

## 更新方法（すでに使っている人）

```bash
git pull
npm install       # 依存パッケージが増えていることがあるため毎回実行
npm run dev       # 再起動
```

`.env.local`（APIキー）や `data/`（同期データ・生成履歴）はそのまま引き継がれます。PostgreSQL を使っている場合のみ、あわせて `npm run db:migrate` を実行してください（何度実行しても安全です）。

> **2026-08-17 更新の補足（PostgreSQL 利用者向け）**: 勝ちセグメントに「年齢×性別」の掛け合わせ次元を追加しました。過去データにはこの次元が無いため、「アカウント管理」タブから対象アカウントの**再バックフィル**を実行すると過去分にも反映されます（未実施でも従来どおり動きます。年齢×性別は通常同期の対象期間（直近7日）から順に蓄積されます）。

## PostgreSQL について（任意）

DB無しでもデータは `data/` フォルダに自動保存され、主要機能はすべて動きます。以下の機能だけDBが必要です：

| DB無しで動く ✅ | DBが必要 ❌ |
|---|---|
| 広告レポート（期間指定・AI分析・異常検知含む） | 勝ちセグメント（性年齢・配置の日次内訳） |
| 優先順位（全期間） | 優先順位の期間指定 |
| バナー生成・勝ち分析再現・生成履歴すべて | 過去実績の月次一括取込（バックフィル） |
| 評価設定の保存・アカウント登録・同期 | クリエイティブ詳細の内訳表示 |

使いたくなったら後から追加できます：

```bash
# macOS の例
brew install postgresql@16 && brew services start postgresql@16
createdb ad_studio
# .env.local に追記: DATABASE_URL=postgres://localhost:5432/ad_studio
npm run db:migrate
```

Windows は [postgresql.org](https://www.postgresql.org/download/windows/) のインストーラを使い、`DATABASE_URL=postgres://postgres:<設定したパスワード>@localhost:5432/postgres` を設定してください。

## 環境変数一覧（.env.local）

| 変数名 | 必須? | 用途 |
|-------|------|------|
| `META_ACCESS_TOKEN` | 分析に必須 | Meta Graph API（ads_read 権限のトークン） |
| `OPENAI_API_KEY` | どちらか推奨 | 画像生成・vision分類・テキスト生成 |
| `GEMINI_API_KEY` | どちらか推奨 | テキスト・分析・画像生成（設定するとGemini優先） |
| `POYO_API_KEY` | 任意 | 画像生成（PoYo経由エンジン） |
| `DATABASE_URL` | 任意 | ローカルPostgres接続文字列 |
| `GEMINI_TEXT_MODEL` / `GEMINI_IMAGE_MODEL` | 任意 | Geminiモデルの固定指定（既定: `gemini-flash-latest` / `gemini-3-pro-image`） |
| `BASIC_AUTH_USER` / `BASIC_AUTH_PASS` | 任意 | 設定するとBasic認証がかかる（ローカル利用では通常不要） |
| `DEMO_MODE` | 任意 | `1` でデモモード（架空データ・Meta API未接続）。`npm run demo` はこれを立てて起動するだけ |

## トラブルシューティング

| 症状 | 原因と対処 |
|------|-----------|
| `npm run dev` で起動しない | Node.js が古い可能性。`node -v` で 20.9 以上か確認 |
| 起動時に `Cannot find module 'sharp'` | `npm install` をやり直す（社内プロキシ環境ではバイナリ取得に失敗することがあります） |
| AI分析で「model ... is no longer available」 | 旧バージョンのコードです。`git pull` して再起動してください |
| 「〜には DATABASE_URL の設定が必要です」 | その機能はPostgreSQLが必要です（上の表を参照）。他の機能はDB無しで使えます |
| 同期でエラー | `META_ACCESS_TOKEN` の期限切れ・権限不足（ads_read）・対象アカウントが割り当てられていない、のいずれかが大半です |

## データの保存場所

すべて**自分のPCの中**に保存されます。外部サーバーへの送信は、Meta / OpenAI / Google 等の各APIを呼ぶ通信のみです。

- 広告実績・登録情報: `data/ads/`（またはPostgreSQL）
- デモモードの組み込みDB: `data/demo-db/`
- 生成したバナーと履歴: `data/generated/`
- APIキー: `.env.local`（`.gitignore` 対象。コミットされません）
